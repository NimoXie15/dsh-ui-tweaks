# dsh-ui-tweaks

给 DSH（DeepSeek Harness）的 Web UI 的一批界面微调：装上即生效，无需配置。

## 它解决什么问题

官方界面上有几处用得难受的地方：宽表格会撑出对话区右沿、滚动条贴在屏幕最右端要横跨半屏去够、Windows 关闭「动画效果」时前端动画被系统设置一并关掉、插件版本更新只能去插件管理页挨个看。这个插件把它们一次性修掉。

## 功能

**宽表格越界修复**
- 宽表格（≥4 列）不再撑出对话区，收敛回正文列并支持横向滚动，观察沿裁掉的问题消失

**对话区左侧滚动条**
- 在右侧宽度调整条的左边放一条自绘滚动条：拖拽、点轨道翻页、滚轮转动手感与原生一致，主题跟随明暗
- **只在会话页出现**，切到插件页等非会话页自动移除

**动画修复**
- Windows 关闭「动画效果」时 Chromium 会向网页报告 `prefers-reduced-motion: reduce`，本插件清除前端几十处因此失效的动画规则，让动画恢复
- web 与桌面客户端都生效

**插件更新检查**
- 插件管理页顶部多一枚「检查更新」按钮（刷新按钮左侧，样式与「添加插件」按钮一致）：比对已装插件（官方 `@deepseek-ai` 插件除外）与 npm registry 的版本，有新版本可点上就地更新，支持全部更新与中途取消
- 有插件成功更新后，面板头部会常驻一条「已更新 N 个插件，重启客户端后生效」提示（web 端文案为「重启 dsh 服务并刷新页面后生效」），直到重启前一直可见
- 不检查 dsh 本体，也不检查 `@deepseek-ai` 官方插件——两者的更新都由 dsh 本体的更新流程负责（桌面端自带更新器；web 端本体升级走 `npm install -g @deepseek-ai/dsh@next`）
- 新版本还没过 pnpm 的发布时长窗口（`minimumReleaseAge`，由 dsh 注入给自带 pnpm，默认 24 小时）时，该行标 **「冷静期中」** 并给出可更新时间（精确到分钟，发布时间与判定 cutoff 都能从报错里读到）；点它只展开详情，**不会**发动一次注定失败的安装。详情里另有 **「仍要强制更新到 x.y.z（跳过 24 小时冷却期）」**：点了会先预检——如果 lockfile 里还有别的包也没满 24 小时（门禁会整体拒绝本次安装），就直接拒绝并列出是哪些包；预检干净才进入二次确认，确认后把该版本写进豁免表并直接安装。到期后这一行会自己变回可更新，不用守着
- 安装成功后自动把 profile 的 `minimumReleaseAgeExclude` 归并成「每包一条」，修掉「同一个包名出现多条时只有靠前那条生效、陈旧条目静默遮蔽新条目，导致此后每次安装都失败」这个坑（由 host 半区静默完成，无界面）

**窗口记忆（仅桌面客户端）**
- 官方桌面客户端主窗口每次启动都是固定的 1280×820 居中小窗，本插件让它记住上次的窗口大小、位置和最大化状态，下次启动自动还原
- 原理：官方主进程没有任何窗口状态持久化，而页面层被官方沙箱隔离、拿不到任何窗口能力，所以由插件服务端拉起一个进程外的隐藏 helper（PowerShell + Win32），在窗口刚出现的瞬间把上次的边界设置回去，之后每秒采样窗口布局增量落盘
- 不修改官方客户端任何文件，卸载插件即完全还原官方行为；浏览器版 / web 启动器环境下自动不动作
- 状态与日志存放在桌面 profile 的 `ui-tweaks/` 子目录（`window-state.json` / `window-helper.log`），删除 `window-state.json` 即重置记忆

## 安装

dsh 目前有浏览器版与桌面客户端两种形态，命令里的 `<profile>` 就是安装目标环境：浏览器用 `web`，桌面客户端用 `desktop`。

```sh
dsh plugin --profile <profile> add @nimoxie/dsh-ui-tweaks
```

- 浏览器版（`web`）：装完重启服务（关掉再 `dsh web`）。
- 桌面客户端（`desktop`）：桌面 profile 由客户端独占管理，请在客户端的「插件管理」页添加本包（包名 `@nimoxie/dsh-ui-tweaks`）。

卸载（CLI 可管理的环境）：

```sh
dsh plugin --profile <profile> remove @nimoxie/dsh-ui-tweaks
```

别人也可以从 GitHub 或本地目录装（开发用）：

```sh
dsh plugin --profile <profile> add github:NimoXie15/dsh-ui-tweaks
dsh plugin --profile <profile> add link:/absolute/path/to/dsh-ui-tweaks
```

> **要求**：dsh `>= 0.2.0-rc.1`（需要 `remote.pluginManager` / `remote.pluginInventory` 接口）。
>
> 升级插件后如果界面没变化，按 **Ctrl+Shift+R** 强刷一次（浏览器可能还在用缓存的旧版本）。

## 已知限制

- 非 npm 来源的插件没有可比的 registry 版本，直接跳过比对：`link:` / `file:` 本地路径标「本地链接」；`git:` / `github:` / `http` 直装标「Git 直装」（例如 `github:Fisfzy/dsh-ego-browser` 会显示为 Git 直装，即使 npm 上有同名包，装的也是仓库源码、与 npm 版本不是一回事）
- `@deepseek-ai` 官方插件直接从检查列表里剔除：它们的更新由 dsh 本体流程负责
- 更新走 profile 内的插件安装接口，与官方插件管理页同源；安装按 registry 解析出的**精确版本号**发起（而非 `@latest`），装的就是面板显示的那一个版本
- **精确版本号并不能绕过 pnpm 的发布时长策略**（`minimumReleaseAge`，由 dsh 注入，默认 24 小时，不在任何配置文件里）：门禁在解析之前先校验 profile 现有的 lockfile，窗口内的版本会让整个 profile 的安装被**整体中止**（`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`，exit 1）。所以这类行被判成「冷静期中」而不是「更新失败」——发布满 24 小时后重试即可
- 更新失败时行内会直接给出原因（pnpm 的输出、退出码与日志路径），不再只说一句「失败」；渲染前会剥掉终端转义序列（否则第一屏是一串乱码），同一份 pnpm 输出被 dsh 摘成两段时只留更完整的一份；失败行可点击重试。冷静期不是失败，不渲染那一长串，只在展开详情里给完整诊断。取消只作用于你点的那一项：取消排队的项不影响正在装的，取消正在装的也不会丢掉后面排队的（它会自动接着装）
- 面板比对用的是 npm 官方 registry，而安装走你本机 pnpm 配置的源（如 npmmirror 镜像）。镜像尚未同步到的新版本会出现「面板说有新版、装时报找不到版本」，稍后镜像同步后重试即可
- 个别插件（如社区插件管理页扩展）自带单独的「检查更新」入口，与本插件的检查互不关联，结果可能不同
- 与启动器 dsh-web-shell 的分工：对话区滚动条、宽表格修复等界面增强已由本插件接管，dsh-web-shell 自身不再注入；其「检查更新」按钮仍负责 **dsh 本体**的比对与升级提示
- 窗口记忆是进程外 Win32 实现（预编译 DLL + PowerShell 进程内加载，不会弹任何安全提示）。实测官方客户端在插件被加载**之前**就把窗口显示出来了，所以「显示前归位」做不到；可达的是显示后约 0.2~1 秒归位（其中大部分时间被官方客户端自己的启动顺序占用，插件能压缩的只有自己那 0.2 秒），归位用「隐藏→移动→显示」把跳变压到一帧。窗口最小化不会中断记忆。把 `window-state.json` 删掉即可忘记记忆；若未来官方客户端自带了窗口记忆，两者会互相覆盖，届时应停用本功能
